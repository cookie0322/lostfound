## 三、与架构决策的对应（影响分析时查这张表）

| 架构决策 | 落点 |
|---|---|
| 占用表只存活跃占用 + `item_id` 唯一索引 | `claim_hold.uk_hold_item`，终态时 `delete` |
| 认证接口 + 本地实现隔离 KV-01 | `AuthApi` / `LocalAuthApi`，`lf.auth.mode` 切换 |
| 状态机 = 一个类 + 转移表，不做引擎 | `ClaimStateMachine` + `claim_transition` |
| 审计统一入口 | 状态机与拦截器统一调用 `AuditRecorder`，DB 只授 INSERT |
| 通知留在模块内显式调用 | `ClaimStateMachine` 内 `switch(event)` 直接调 `NoticeService` |
| 可见性判断独立 | `ClaimAppService#voucherVisible` + `ClaimView` |
