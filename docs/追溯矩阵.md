# 需求—代码追溯矩阵

用途：把《需求分析专项》的 FR / QR 编号逐条对应到实现位置与验证方式，
用于实验报告、答辩追溯，以及回答"这条需求你写在哪了"。

状态说明：**已验证** = 有可复现的测试或实测证据；**待取证** = 代码已实现但缺截图/压测；**部分** = 有已知缺口。

## 三、与架构决策的对应

| 架构决策 | 落点 |
|---|---|
| 占用表只存活跃占用 + `item_id` 唯一索引（3.1 决策 12） | `claim_hold.uk_hold_item`，终态时 `delete` |
| 认证接口 + 本地实现隔离 KV-01（D-02） | `AuthApi` / `LocalAuthApi`，`lf.auth.mode` 切换 |
| 状态机 = 一个类 + 转移表，不做引擎（D-03） | `ClaimStateMachine` + `claim_transition` |
| 审计统一入口（D-04） | 状态机与拦截器统一调用 `AuditRecorder`，DB 只授 INSERT |
| 通知留在模块内显式调用（D-04） | `ClaimStateMachine` 内 `switch(event)` 直接调 `NoticeService` |
| 可见性判断独立（KV-03） | `ClaimAppService#voucherVisible` + `ClaimView`，不散落在业务里 |
