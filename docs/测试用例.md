# 测试用例（质量需求 QR-01 ~ QR-10）

本文档回答两个问题：**每条质量需求怎么测**、**黑盒与白盒分别覆盖了什么**。

- **黑盒**：只通过 HTTP 接口或页面观察输入输出，不关心内部结构；用等价类划分、边界值、错误推测设计用例。
- **白盒**：看代码结构，用语句/分支/路径覆盖设计用例；本项目用它覆盖状态机与拦截器这类"分支多、容易漏"的地方。

自动化用例在 `backend/src/test/java/edu/campus/lostfound/` 下，`.\mvnw.cmd test` 一条命令跑完。

## 二、按质量需求逐条设计

|---|---|---|---|---|
| 黑盒 | TC-QR01-01 票据换取耗时 | 后端已启动 | 连续 100 次 `POST /api/auth/bind`（每次新票据），记录耗时 | 单次 < 1s |
| 黑盒 | TC-QR01-02 列表接口并发 | 有 ≥20 条招领信息 | JMeter 20 线程压 `GET /api/items` 与 `GET /api/claims/mine`，统计 P95/P99 | P95 ≤ 2s、P99 ≤ 3s |
| 白盒 | TC-QR01-03 热点路径走查 | — | 代码走查：票据换取在内存 `ConcurrentHashMap` 完成，无外部 HTTP 调用；列表查询命中 `idx_item_status`、`idx_claim_applicant` | 无 N+1、无全表扫描 |

### QR-02 安全（不采集联系方式与密码，只存学号与姓名）

| 方法 | 用例 | 步骤 | 预期 |

## 三、白盒覆盖说明（为什么这样设计）

| 被测单元 | 覆盖方法 | 覆盖结果 |
|---|---|---|
| `ClaimStateMachine#transition` | 路径覆盖：12 条合法迁移 + 终态 2×9 非法迁移 + 未知事件 | 规则查找、非法拒绝、`end_reason` 映射、终态副作用四条分支全覆盖 |
| `AuthInterceptor#preHandle` | 分支覆盖：非 Controller / 无注解 / 未登录 / 角色不符 / 角色匹配 | 5 个分支全覆盖 |
| `ClaimAppService#apply` | 分支覆盖：未认证 / 特征不足 / 物品不存在 / 状态非 0 / 自领 / 占用冲突 | 黑盒用例覆盖了后四个，前两个由手工验收覆盖 |
| `VoucherStorage` | 等价类：合法图片 / 非法后缀 / 路径穿越 | 后缀白名单与 `startsWith(root)` 两道防线 |
